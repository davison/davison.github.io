@AGENTS.md

## Project

Personal blog, built with [Zensical](https://zensical.org/) (a Python static site generator), hosted on GitHub Pages.

Python toolchain is `uv` + Python >=3.14. Dependencies live in `pyproject.toml`; `zensical` is the only runtime dep.

## Common commands

```sh
# First-time / after-pull: install deps and create .venv
uv sync

# Serve locally on http://localhost:8000 (auto-reload on file changes)
uv run zensical serve

# One-shot build into ./site/ (matches what CI does)
uv run zensical build --clean

# Run the housekeeping script: reconciles drafts in/out, regenerates the
# blog-posts nav block in zensical.toml, regenerates docs/blog/archive.md,
# regenerates docs/atom.xml. CI runs this before every build.
uv run python main.py
```

There is no test suite or linter — CI just runs `main.py` then `zensical build` then deploys.

## Architecture

- **`docs/`** — site source (Zensical's `docs_dir`).
  - `docs/index.md`, `docs/about.md` — top-level pages.
  - `docs/blog/index.md` — blog landing.
  - `docs/blog/posts/YYYY-MM-DD-slug.md` — published posts.
  - `docs/blog/archive.md` — **generated by `main.py`; do not edit by hand.**
  - `docs/atom.xml` — Atom feed at site root, **generated by `main.py`; do not edit by hand.**
  - `docs/assets/images/` — all image assets, served at `/assets/images/...`.
  - `docs/overrides/` — theme partial overrides (`main.html` adds Atom auto-discovery; `partials/content.html` injects a "published on … by …" line under each H1).
  - `docs/stylesheets/extra.css` — supplemental CSS, loaded via `extra_css` in `zensical.toml`.
- **`zensical.toml`** — site config. The block between `# BEGIN_BLOG_POSTS` / `# END_BLOG_POSTS` is rewritten by `main.py` — never edit by hand.
- **`main.py`** — utility script (run in CI). Lifted from `radiusred/www/main.py` minus the multi-repo `sync_docs.py` since davison.github.io is a single-repo blog.
- **`_drafts/`** — gitignored. WIP posts live here; `main.py` will promote any draft whose `date:` has arrived into `docs/blog/posts/` and demote any future-dated post out of it.
- **`.github/workflows/pages.yml`** — builds with Zensical and deploys via `actions/deploy-pages` on push to master, daily at 00:05 UTC (for draft promotion), and `workflow_dispatch`.

## Authoring conventions

Required post frontmatter (use YAML block-list for tags — flow-list `[a, b]` gets misread by Zensical's markdown parser as an unresolved link reference):

```yaml
---
layout: default
author: Darren Davison
title: ...
date: YYYY-MM-DD
description: One-sentence summary, shown on the archive and in the Atom feed.
tags:
  - linux
  - desktop
---
```

- **No `# Title` in the body** — Zensical's overridden `partials/content.html` renders the H1 from frontmatter `title` and splices the published/author meta line in after it. Start the body with the first paragraph or `##` heading.
- **Image references** use root-absolute paths: `![alt](/assets/images/topic/file.jpg)`. These resolve to `https://host/assets/images/...` once deployed.
- **Intra-post links** use directory-style URLs: `[part I](/blog/posts/2019-03-09-multi-room-audio-I/)` — Zensical renders each post as `posts/<slug>/index.html`.

## Drafts and dates

Future-dated posts in `docs/blog/posts/` are moved into `_drafts/` by `main.py`. Drafts whose date has arrived get promoted back into `docs/blog/posts/`. The daily 00:05 UTC cron in the deploy workflow makes this happen without human intervention.
